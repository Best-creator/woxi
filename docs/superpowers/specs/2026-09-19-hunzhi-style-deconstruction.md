> 样本：gzh-crawl 已采混知 8 篇 done / 102 图（`C:/Users/yjt/Desktop/gzh-crawl/data/images/混知/`）。
> 方法：grok-4.6 从 4 篇 8 图提炼的风格画像（`data/styles/混知.json`）**先给出假设**，
> 本文档逐条用屏高切图**人工复核**（科学×2、中国史班级、财经、百科各取开头/中段），
> 修正了画像的过度概括（见 §7.1）。采集侧结论「图外正文只有 5~72 字」实测成立：
> 三篇的图外正文 23/61/48 字，且全是「关注/往期复习」引导语——**混知 100% 的知识内容都烘在图里**。

## 一、一张长图的解剖（版式骨架）

正文是 **600px 宽、3300~7700px 高的竖向长条**，一张 ≈ 6~12 屏；1080 宽的小图全是头尾 banner（栏头/引导）。
自上而下的**循环结构**（从切图归纳，非官方规范）：

```
栏目眉（混知科学—，灰色小字）
└─ 大标题（加粗黑体居中，如「古希腊奇葩说（下）」）
   └─ recap（「上回咱们说到……」2~3 行居中）
      └─ 转场设问（1~2 行）→ 大字关键词行（如「水、火、土、气」）
         └─ 章节标题（编号：1，吴楚之争 / Part1、xxx）
            └─ 文字铺垫（2~3 行）→ 主插图（全宽单幅 / 两人对坐 / 三人围殴）
               ├─ 图解引线（虚线圈 + 引线 + 2 行注释，关键词加粗）
               ├─ 对白气泡（橙底圆角，≤10 字，尾巴指向说话者）
               └─ 旁白头像（圆形红衣青年）+ 橙字吐槽
                → 橙色问题条（「世界上最大的东西是什么？:Q2」）→ 进入下一循环
```

**屏节奏**：文字屏（2~4 行 × 每行 ≤13 字，居中）与图画屏严格交替，一屏只讲一个信息点。
文字屏的作用是「铺垫-转折」，图画屏负责「事件-笑点」，两者从不混在一屏里抢注意力。

## 二、文字系统：四类图内文字（这是混知的真骨架）

| 类型 | 形态 | 字数 | 职责 |
|---|---|---|---|
| 对白气泡 | 橙色圆角色块，尾巴指向说话者 | ≤10 字 | 主线剧情的角色台词 |
| 旁白吐槽 | 圆形头像（黑短发红衣青年，全号固定）+ 旁橙字 | 10~25 字 | 唱反调、点题、吐槽 |
| 图解引线 | 虚线圈 + 引线 + 旁注 | ≤2 行 | 知识注释，关键词加粗 |
| 名字条/问题条 | 橙色横条 | ≤12 字 | 人物登场（外号+名字）、设问推进（Q1/Q2） |

辅助：拟声词（拉丁字母涂鸦 PWOFF!）、放射线/汗滴/速度线等符号语言。
**字体四级**：灰眉题 → 黑大标题 → 黑正文 → 加粗关键词；橙色专属于「条」。

## 三、画面与色彩

- **白底 90% 留白**：场景极简到一根地平线，角色直接站在白纸上；从不画完整背景。
- **粗黑手抖描边**：外轮廓 2~4px 带顿挫，五官衣褶细线；几乎无灰阶，体积靠轮廓与短排线。
- **Q 版 1:3 头身**，表情公式化（粗短眉/小圆眼），情绪靠符号不靠刻画。
- **群体演出**：单主角图很少，常见「两人对坐抬杠」「三人围殴」「全班围观」——事件发生在关系里。
- 色彩语义：白=底、黑=线稿+正文、青绿=班级校服、**橙=一切「条」（气泡/注释/名字/问题）**、
  明黄=栏头大字、红=小面积点缀。

## 四、叙事节拍器（最值得抄的部分）

1. **冷开场设问**：「在古希腊做个文化人要具备什么素质？那一定就是……打嘴炮！」——先抖包袱再进正题。
2. **固定 recap 句式**：「上回咱们说到……」——系列文章每篇都接得上。
3. **外号命名节拍**：新概念登场 = 起外号 + 立绘 + 名字条（「古希腊『完美』三贱客：托勒密/毕达哥拉斯/亚里士多德」）。
   命名即笑点，知识点的名字是被「安」上去的。
4. **设问推进**：橙色问题条 Q1/Q2，用问题当下一屏的钩子，代替「接下来」「其次」。
5. **固定旁白角色**：红衣青年全号通用，负责唱反调与点题——读者对他的反应本身成为预期。
6. **自嘲梗**：故意「放错图」再收回（「额，不好意思，放错图了」）——节奏型笑点，零成本。
7. **时代错位/方言梗**：奥利给、热干面、BB King——把史实钉在当代口语上。

## 五、与本项目的对照

**已有（这次剧情漫画 Phase 1 已对齐）**：群体拟人化演出（四只袋熊）、白底硬规则、一段一梗两拍、
段 60/句 22 字数红线、段图串联、文字带卡片化。

**差距（按重要度）**：

| # | 差距 | 混知做法 | 我们现状 |
|---|---|---|---|
| 1 | 画风 | 粗黑线 Q 版手绘、白底 | 日系赛璐璐（live 实测出的袋熊图） |
| 2 | 对白 | 气泡在图内，≤10 字 | 红线「画面不写字」，台词全在文字带 |
| 3 | 旁白角色 | 固定红衣青年人设 | 无 |
| 4 | 命名/设问节拍 | 外号+名字条、Q 问题条 | 提示词未要求 |
| 5 | 正文排版 | 居中、每行 ≤13 字 | 文字带左对齐（标题条+正文） |
| 6 | 多格 | 每屏常 1 格大图，偶多格 | Phase 3 计划 2~4 格 |

**红线冲突（需要拍板）**：混知的魂之一是气泡对白，而我们的红线「画面不写字」是当初为防生图错字立的。
两条路：**(a)** 放开极短气泡（≤6~10 字）让生图画——混知味的对白，但错字风险真实存在；
**(b)** 文字不进生图，Phase 2 的「旁白条/对白条」由渲染器烘字（canvas 排版绝不写错），气泡感由条样式给。
推荐 **(b)**：混知的字之所以不写错，是因为那是画师排的字，不是模型画的字；我们的段图本来就是「图归生图、字归排版」。

## 六、落地路径建议

- **P0（零代码，一条 API）**：风格画像已按 `StyleExportFileSchema` 同名字段导出
  （`gzh-crawl/data/styles/export-for-woxi.json`）→ `POST /api/style-library` 即入风格库，
  之后第三/四步选它作为绘制风格，出图立刻换皮。**注意先修画像的过度概括（§7）再导。**
- **P1（提示词层，半天）**：story_comic 设计器提示词吸收节拍器 1/2/3/4：冷开场设问、固定 recap 句、
  外号命名帧（立绘+名字交给文字条）、设问过渡；红线不动。
- **P2（引擎层，= 原 Phase 2）**：旁白条/对白条块类型（渲染器烘字 + 橙色条样式 + 固定旁白头像位），
  这是「混知味」的真正载体；Phase 3 多格顺路。
- **P3（排版微调）**：文字带正文改居中、每行 ≤13 字断行（渲染 metrics 改动小）。
