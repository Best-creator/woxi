# Unified Content Workflow Design

## Goal

将文章创建、资料准备、大纲审核、正文生成和配图规划整合到一个清晰的文章工作台中，并确保正文生成在用户明确操作后调用已配置的 LLM，而不是把大纲或演示数据直接映射成正文。

## User Flow

文章详情页 `/articles/[id]` 是统一入口，顶部显示四步进度：

1. 资料
2. 大纲
3. 正文
4. 配图

当前步骤通过 URL 查询参数保存，例如 `/articles/[id]?step=outline`，刷新和浏览器前进后退都能恢复。旧入口 `/articles/[id]/outline` 保留，并进入同一工作台的大纲步骤。

步骤状态由文章数据决定：

- 资料：始终可进入；资料面板支持新增、编辑、启用和删除。
- 大纲：有主题即可进入；生成后必须完成审核并确认，才能解锁正文。
- 正文：必须存在已确认大纲；点击“生成正文”才调用正文生成接口。
- 配图：必须存在正文 blocks；点击后调用现有图片规划接口。

点击未解锁步骤时显示解锁条件，不执行生成请求。已完成步骤可以回看和编辑；修改上游步骤后，下游状态变为需要重新确认或重新生成。

## Backend Changes

### Outline

保留现有大纲生成、审核、确认和版本接口，统一工作台复用这些操作。大纲页不再作为独立工作流终点。

### Article Generation

将 `POST /api/articles/[id]/generate` 改为接收：

```json
{
  "expectedUpdatedAt": "ISO datetime",
  "model": "optional model id"
}
```

服务端验证文章存在、版本未冲突、知识简报存在、大纲已确认。正文生成器使用主题、知识简报、已确认大纲和启用资料作为输入，返回标题和正文 blocks；不得重新生成或覆盖已确认大纲。

有 LLM 配置时使用 OpenAI 兼容 JSON 客户端和明确的正文 JSON schema；无配置时保留演示生成器作为显式 fallback。正文生成结果写入文章版本并将状态推进到 `editing`。

### Images

复用现有 `/image-plan`、图片资产编辑和占位图刷新接口。统一工作台只负责步骤切换和操作入口，不改变图片资产数据模型。

## Frontend Structure

- 新增 `WorkflowStepper`，展示步骤名称、完成状态、锁定状态和当前步骤。
- `ArticleWorkspace` 按 active step 渲染资料、大纲、正文或配图操作区。
- 大纲工作区抽取为可嵌入的内容组件，保留现有审核、确认、版本回溯行为。
- 正文步骤显示正文编辑器、生成按钮、模型选择和生成状态；未生成时显示明确空状态。
- 配图步骤显示现有图片规划面板。
- 顶部保留保存状态、预览和文章标题，但去除重复的侧栏导航和“跳回主页面”式入口。
- 移动端将步骤栏变为可横向滚动的固定控件，操作区单列显示。

## State and Error Handling

- 所有生成操作使用 `expectedUpdatedAt` 做乐观并发校验。
- 生成期间禁用当前步骤的编辑和重复提交。
- API 错误在当前步骤显示，不跳转页面。
- 上游步骤发生修改时，清除或标记下游审核/生成结果过期。
- LLM 返回格式继续通过 Zod schema 校验，并保留服务端脱敏错误信息。

## Testing

- 为正文生成器增加 LLM JSON schema、Prompt 输入和结果持久化测试。
- 为生成路由增加未确认大纲、模型透传、冲突和演示 fallback 测试。
- 为 `WorkflowStepper` 增加当前、完成和锁定状态测试。
- 为统一工作台增加步骤切换、锁定条件、正文真实生成请求和配图入口测试。
- 运行完整 Vitest、ESLint、TypeScript、Next build，并执行现有 Playwright 工作流。
