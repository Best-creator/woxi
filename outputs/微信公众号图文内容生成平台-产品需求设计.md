# 微信公众号图文内容生成平台：产品需求设计

- 文档版本：1.0
- 日期：2026-09-09
- 产品阶段：个人创作者 MVP
- 文档状态：已确认；阶段 1 已合并基础框架与首个纵向闭环

## 1. 产品概述

本产品面向个人内容创作者，将一个知识点转化为浅显、准确、图文结合且适合微信公众号发布的文章。产品不是“一键生成黑盒”，而是一套结构化创作工作台：先梳理知识和确认大纲，再分章节生成正文、规划配图、块级编辑，最后预览并复制到微信公众号后台。

### 1.1 核心价值

1. 降低把专业知识转化为通俗内容的难度。
2. 把全文反复重写变成可控的分阶段、局部修改。
3. 将插画、知识图解和公众号排版纳入同一工作流。
4. 尽可能展示内容依据，降低 AI 编造和误用资料的风险。

### 1.2 目标用户

第一版只服务单个个人创作者。用户需要持续输出微信公众号知识类文章，但缺少资料整理、知识拆解、配图或排版时间。

### 1.3 核心成功标准

用户能够在 5 分钟内从知识点获得可编辑初稿，并主要通过局部调整完成一篇 2,000 至 3,000 字、包含 3 至 5 张图片的可发布文章。复制到微信公众号后台后，不需要重新整理正文结构和主要样式。

## 2. 范围

### 2.1 MVP 范围

- 单个创作者账号和一份默认写作档案。
- 创建、保存、复制和删除文章项目。
- 仅输入知识点的快速模式。
- 知识点加参考资料的资料模式。
- 支持粘贴文本、网页链接，以及 PDF、DOCX、TXT、Markdown 文档上传。
- 知识梳理、参考来源展示和可编辑大纲。
- 全文或分章节生成、局部改写及版本保留。
- AI 插画和结构化知识图解的规划、生成与替换。
- 块级文章编辑、自动保存、撤销和历史恢复。
- 公众号主题、移动端预览和富文本一键复制。

### 2.2 明确不在 MVP 范围

- 团队空间、角色权限、审批和多人实时协作。
- 套餐、额度售卖、支付、发票和复杂运营后台。
- 多公众号品牌管理。
- 自动选题、批量内容生产和内容日历。
- 微信公众号接口绑定、草稿箱同步和直接发布。
- 完整素材管理系统和发布后的阅读数据分析。
- 对所有事实进行人工级别的自动审核或作出绝对正确承诺。

## 3. 产品原则

1. **先结构、后正文：** 知识梳理和大纲必须可见、可编辑、可确认。
2. **用户修改优先：** AI 任务不得覆盖用户已修改的非目标内容块。
3. **来源可见：** 来源明确的事实应能追溯；没有可靠来源的内容标记为“AI 补充”。
4. **局部可重做：** 章节、内容块和图片均可单独重新生成并保留旧版本。
5. **生成与排版分离：** 文章保存为结构化内容块，预览或复制时才渲染为公众号 HTML。
6. **控制第一版范围：** 先验证单篇文章的质量和效率，不建设内容工厂。

## 4. 核心用户流程

```text
登录
  -> 创建文章
  -> 输入知识点
  -> 选择快速模式或添加参考资料
  -> 调整本篇写作参数
  -> AI 获取和整理资料
  -> 查看知识梳理结果
  -> 生成、编辑并确认大纲
  -> 生成全文或逐章生成
  -> 确认配图计划
  -> 生成插画和知识图解
  -> 块级编辑与局部重写
  -> 选择公众号主题并预览
  -> 一键复制到微信公众号后台
```

文章状态固定为：

```text
草稿
  -> 知识梳理中
  -> 等待确认大纲
  -> 正文生成中
  -> 配图生成中
  -> 编辑中
  -> 待发布
```

失败或取消是生成任务的状态，不覆盖文章当前状态和已经完成的内容。

## 5. 功能需求

### 5.1 账号与写作档案

#### 用户故事

- 用户可以登录自己的工作台并访问历史文章。
- 用户可以保存一套默认写作风格，新建文章时自动继承。
- 用户可以临时调整单篇文章的参数，而不修改默认档案。

#### 配置字段

- 目标读者。
- 读者已有知识水平。
- 文章语气。
- 目标篇幅。
- 专业程度。
- 常用文章结构。
- 常用称呼和表达。
- 禁用词及不希望出现的表达。

#### 验收标准

- 未登录用户不能读取文章和资料。
- 新文章自动复制当前默认档案作为文章级配置快照。
- 修改文章级配置不影响默认档案，修改默认档案也不追溯修改旧文章。

### 5.2 创作项目

#### 用户故事

- 用户可以创建、重命名、复制和删除文章。
- 用户可以从文章列表继续最近编辑的项目。
- 用户可以查看文章当前阶段和最近保存时间。

#### 验收标准

- 创建文章只要求填写知识点。
- 删除前必须确认；删除采用可恢复的软删除策略。
- 复制文章会复制结构化内容和配置，但不会复制正在运行的生成任务。
- 列表默认按最近更新时间倒序显示。

### 5.3 内容输入与资料处理

#### 输入模式

**快速模式：** 用户只输入知识点，系统检索公开信息并建立来源集合。

**资料模式：** 用户输入知识点并提供文本、网页链接或文档。系统优先使用用户资料，仅在发现明显知识缺口时补充公开来源，并明确区分两类来源。

#### 验收标准

- 用户可以添加、预览、启用、停用和删除单个来源。
- 单篇文章最多添加 10 个来源；单个上传文件不超过 20 MB，支持 PDF、DOCX、TXT 和 Markdown。
- 每个来源显示标题、类型、处理状态和抓取或上传时间。
- 网页抓取或文档解析失败时，其他来源仍可继续处理。
- 外部网页中的脚本、样式和提示性指令不得进入模型系统指令；网页内容一律作为不可信资料处理。
- 系统保留来源元数据和必要的文本片段，不默认公开转载完整原文。

### 5.4 知识梳理与大纲

#### Knowledge Brief 输出

- 一句话解释。
- 核心概念。
- 理解该知识点所需的前置知识。
- 容易误解的地方。
- 可用于解释的类比或例子。
- 关键事实与来源对应关系。
- 缺少可靠依据的内容。

#### 大纲能力

- 根据 Knowledge Brief 和写作档案生成大纲。
- 新增、删除、改名和拖动章节。
- 单独重新生成某个章节建议或重新生成整份大纲。
- 用户明确确认后才进入正文生成。

#### 验收标准

- Knowledge Brief 的所有字段均可编辑或删除。
- 有来源的关键事实可以打开对应来源和相关片段。
- 无可靠来源的补充信息必须有醒目标记。
- 重新生成大纲时保留上一版，用户确认后才替换当前版本。

### 5.5 正文生成与局部改写

#### 用户故事

- 用户可以一次生成全文，也可以只生成选定章节。
- 用户可以对一个或多个内容块执行改写、缩短、扩写、口语化、举例或自定义指令。
- 用户可以比较新旧版本并决定是否替换。

#### 验收标准

- 正文按章节写入独立内容块，不保存为不可拆分的长文本。
- 局部生成只修改任务明确指定的章节或内容块。
- 生成过程中，用户已经手动修改的其他内容不得被后台结果覆盖。
- 每次替换前保留旧版本，用户可以撤销。
- 正文生成遵守文章级写作参数，并使用已确认的大纲和启用的来源。

### 5.6 配图规划与生成

#### 图片类型

- **AI 插画：** 用于封面、场景和章节过渡，强调视觉吸引力。
- **知识图解：** 用于概念、流程、对比、结构和总结，强调信息准确和中文可读性。

知识图解优先由模型输出结构化图解数据，再使用受控的 HTML/Canvas 模板渲染；不依赖图片模型直接生成大量中文文字。AI 插画由图片模型生成。

#### 配图工作流

1. 系统根据大纲和正文提出配图位置、类型、用途及提示词。
2. 用户可以接受、修改或删除建议。
3. 用户确认后才触发图片生成。
4. 每张图可查看候选版本、重新生成、替换、删除或上传本地图片。

#### 验收标准

- 图片生成失败不会阻塞正文编辑。
- 正式图片保留提示词、模型、尺寸和生成时间。
- 知识图解中的文字可编辑，重新渲染不会修改文章正文。
- 所有图片生成公众号适用的压缩版本，并保留原始版本。
- 图片块包含替代文本字段，便于无障碍和失败回退。

### 5.7 块级编辑器

#### 支持的内容块

- 一级、二级和三级标题。
- 正文段落。
- 有序和无序列表。
- 引用。
- 强调提示块。
- AI 插画。
- 知识图解。
- 总结卡片。
- 分隔元素。

#### 验收标准

- 用户可以新增、删除、复制和拖动内容块。
- 支持标准文本编辑、撤销和重做。
- 编辑操作在短暂空闲后自动保存；保存失败时在本地暂存并显示未保存状态。
- 页面刷新或网络恢复后能够恢复最近一次有效内容。
- 生成任务进行时，编辑器保持可用，并清楚标识受任务影响的内容块。

### 5.8 主题、预览与复制

#### MVP 能力

- 至少提供三套克制、适合知识内容的公众号主题。
- 支持手机正文宽度预览。
- 展示标题层级、字体、行距、段距、引用、卡片和图片效果。
- 将结构化内容渲染为使用内联样式的公众号兼容 HTML。
- 通过浏览器剪贴板复制富文本，并提供手动选择复制的回退方式。

#### 验收标准

- 切换主题不修改文章原始内容块。
- 预览与复制结果使用同一个渲染器，避免两套规则产生差异。
- 在项目支持的 Chrome 和 Edge 当前稳定版中，粘贴到微信公众号编辑器后保留标题层级、段落、强调、引用、图片和主要间距。
- 图片使用可公开访问的 HTTPS 地址，且在粘贴后的微信公众号编辑器中可见。
- 若浏览器拒绝剪贴板权限，用户仍可通过明确的回退操作复制内容。

### 5.9 历史与恢复

#### 验收标准

- 重大操作前创建版本快照，包括全文生成、整体大纲替换和主题渲染规则升级。
- 用户可以查看快照时间和原因，并将文章恢复到指定快照。
- 恢复操作本身也创建快照，避免恢复后无法返回。

## 6. 页面设计

### 6.1 文章列表

展示文章标题、状态、最近更新时间和快捷操作。支持新建、继续编辑、复制和删除。

### 6.2 新建文章

包含知识点输入、快速/资料模式切换、资料添加区和本篇写作参数。主操作为“开始知识梳理”。

### 6.3 知识与大纲确认页

上半部分展示 Knowledge Brief 和来源，下半部分展示可排序大纲。用户确认大纲后进入正文生成。

### 6.4 图文编辑工作台

- 左侧：大纲、章节状态和快速跳转。
- 中间：块级文章画布。
- 右侧：AI 操作、内容块设置、配图设置和主题设置。
- 顶部：保存状态、任务状态、预览和复制入口。

桌面端是 MVP 的主要编辑环境。移动端第一版保证可预览和查看，不承诺完整块级编辑体验。

### 6.5 公众号预览页

以公众号正文宽度展示最终效果，支持主题切换、问题提示和一键复制。

## 7. 技术架构

MVP 采用模块化单体应用加异步任务队列，不拆分微服务。

### 7.1 组件

| 组件 | 职责 |
|---|---|
| Web 创作端 | 页面、块级编辑、生成控制和预览 |
| 业务 API | 账号、文章、内容块、版本和素材管理 |
| AI 编排器 | 组织知识梳理、大纲、正文、配图和质量检查步骤 |
| 模型网关 | 文本及图片模型接入、路由、限流、重试和费用记录 |
| 资料处理器 | 网页抓取、文档解析、清洗、切分、检索和引用定位 |
| 图片服务 | 图片任务、候选版本、压缩和知识图解渲染 |
| 排版渲染器 | 内容块到预览页面和公众号 HTML 的转换 |
| 异步任务系统 | 长任务进度、取消、超时和失败重试 |
| 关系型数据库 | 结构化业务数据和任务状态 |
| 对象存储 | 原始资料、解析结果、图片和导出资源 |

### 7.2 模块边界

- Web 端不直接调用模型供应商，只调用业务 API。
- AI 编排器通过模型网关访问模型，业务模块不绑定具体供应商。
- 资料处理器输出统一的来源和文本片段结构，屏蔽网页与文档差异。
- 编辑器只消费结构化内容块，不理解 AI 编排细节。
- 排版渲染器只消费内容块和主题，不读取模型输出原文。

### 7.3 核心数据对象

| 对象 | 说明 |
|---|---|
| User | 单个创作者账号 |
| UserProfile | 默认写作档案 |
| ArticleProject | 文章元数据、当前状态和文章级配置 |
| SourceDocument | 用户资料或系统检索来源 |
| SourceChunk | 可检索资料片段和来源位置 |
| KnowledgeBrief | 核心概念、误区、依据和补充说明 |
| OutlineSection | 可排序的文章章节 |
| ContentBlock | 类型、内容、顺序、版本和来源关联 |
| ImageAsset | 图片文件、类型、提示词和候选版本 |
| GenerationTask | 任务类型、输入版本、状态、进度、模型和费用 |
| VersionSnapshot | 可恢复的文章快照 |
| PublishTheme | 公众号排版规则和版本 |

### 7.4 AI 生成链路

```text
知识点
  -> 获取用户资料和/或公开来源
  -> 清洗、切分、去重和检索
  -> 生成 Knowledge Brief 与事实来源映射
  -> 生成并确认大纲
  -> 按章节生成正文内容块
  -> 规划配图位置、类型和用途
  -> 生成 AI 插画或渲染知识图解
  -> 检查来源、重复、结构和图片规格
  -> 进入编辑、预览与复制
```

每个任务携带目标内容版本。任务完成时若目标已经被用户修改，系统不得静默覆盖，而应把结果保存为候选版本供用户选择。

## 8. 异常处理

每个生成任务具有 `pending`、`running`、`succeeded`、`failed` 和 `cancelled` 状态，并记录输入摘要、目标版本、模型、耗时、费用和错误类别。

| 异常 | 产品行为 |
|---|---|
| 网页或文档解析失败 | 标记失败来源并允许重试、替换或粘贴正文，不阻塞其他来源 |
| 没有可靠来源 | 允许继续，但突出显示缺少依据的内容 |
| 模型输出格式错误 | 自动执行格式修复，失败后进行有限次数重试 |
| 正文生成失败 | 保留现有章节，只允许重试失败章节 |
| 图片生成失败或超时 | 保留图片占位块，允许稍后重试或本地上传 |
| 用户取消任务 | 停止未完成步骤，保留已经完成的结果 |
| 自动保存失败 | 本地暂存，显示未保存状态，恢复连接后重试 |
| 新结果与用户编辑冲突 | 保存为候选版本，由用户决定是否替换 |
| 模型限流或服务不可用 | 指数退避后有限重试，仍失败则展示可操作的错误信息 |

错误信息面向用户描述“发生了什么、哪些内容已保留、下一步能做什么”，不显示供应商原始异常或内部提示词。

## 9. 成本与性能

### 9.1 成本策略

- 大纲、分类和普通改写优先使用低成本模型。
- 知识梳理、复杂写作和最终检查使用能力更强的模型。
- 分章节生成，修改时只处理目标内容块。
- 相同资料解析结果复用；相同输入短时间内不重复发起任务。
- AI 插画先生成预览版本，用户确认后再生成正式尺寸。
- 单篇文章记录文本、检索、图片和存储成本。
- 以 2,000 至 3,000 字和 3 至 5 张图为基准，MVP 目标平均供应商成本不超过人民币 5 元，默认硬上限为人民币 10 元；达到上限前提示用户并停止新的付费生成操作。

### 9.2 性能目标

- 常规文章列表和编辑页面在正常网络下 2 秒内呈现可操作界面。
- 编辑操作在停止输入 2 秒内触发自动保存。
- 长任务在 2 秒内显示已接受状态，并持续展示阶段和进度。
- 从提交知识点到出现可编辑初稿的目标时间不超过 5 分钟，不包含用户等待确认大纲的时间。

## 10. 安全与内容风险

- 上传文件进行类型、大小和恶意内容检查，不执行其中的宏、脚本或嵌入程序。
- 抓取网页时隔离脚本和样式，将网页文本视为不可信输入，防范资料中的提示注入。
- 用户资料和未发布文章默认私有，不用于训练公共模型；具体模型供应商必须选择符合该约束的接口配置。
- 日志不记录完整敏感资料和访问凭据。
- 对明显违法、侵权或平台禁止内容给出提示，并遵守所选模型供应商的内容政策。
- 来源展示不等于事实担保；发布前由用户承担最终审核责任。

## 11. 测试与质量评估

### 11.1 黄金测试集

建立 30 至 50 个固定知识点，覆盖科技、商业、历史和生活常识，并包含：

- 只输入知识点的案例。
- 附带高质量资料的案例。
- 资料相互矛盾的案例。
- 资料不足、网页失败或文档格式异常的案例。
- 需要流程图、对比图、结构图或插画的案例。

### 11.2 自动化测试

- 单元测试：内容块操作、版本比较、渲染规则、资料清洗和费用计算。
- 结构契约测试：AI 输出必须满足指定结构，缺失字段能够被识别和修复。
- 集成测试：数据库、对象存储、任务队列、模型网关和重试流程。
- 端到端测试：从创建文章到公众号复制的完整主流程。
- 并发与冲突测试：生成任务返回时用户已修改目标内容。
- 故障测试：模型限流、超时、网页失败、存储失败和断网恢复。

### 11.3 人工质量指标

每个黄金案例按 5 分制评估事实准确性、通俗程度、结构完整性、风格符合度、引用可追溯性和配图有效性。内测上线要求：

- 80% 以上案例的六项平均评分达到 4 分。
- 95% 以上已展示的来源链接可以打开或定位到保存的来源信息。
- 所有缺少可靠依据的内容均有可见标记。
- 局部生成测试中，非目标内容块零静默覆盖。

### 11.4 微信兼容性测试

使用 Chrome 和 Edge 当前稳定版，将至少 20 篇覆盖全部内容块类型的文章复制到微信公众号编辑器，检查标题、段落、强调、引用、图片、卡片、间距和超长文本。所有阻塞发布的问题必须修复；非阻塞的像素级差异需记录为已知限制。

## 12. 产品指标

- 从创建文章到首个可编辑初稿的时间。
- 用户确认大纲前的平均修改次数。
- 内容块生成结果的直接接受率。
- 每篇文章的局部重写次数和全文重做率。
- 配图建议接受率及图片重生成次数。
- 自动保存失败率和任务失败率。
- 公众号复制成功率。
- 单篇文章平均供应商成本。

MVP 的核心验证信号是：至少 80% 的内测文章主要依靠局部修改完成，而不是删除后重新生成全文。

## 13. 实施阶段与依赖

### 阶段 1：基础框架与首个纵向闭环，约 1 周

- 建立 Web 应用、数据模型、模块边界、自动化测试和本地开发环境。
- 打通“创建文章 -> 生成模拟 Knowledge Brief 与大纲 -> 生成结构化内容块 -> 公众号预览 -> 富文本复制”的可运行闭环。
- 在真实页面中验证公众号内联样式和图片可见性，不再制作独立验证原型。
- 建立资料处理、模型网关、图片服务和任务队列接口；第一阶段允许使用本地模拟适配器。
- 用一个结构化知识图解样例验证中文排版和导出效果。

通过标准：应用可以本地运行并完成纵向闭环；核心领域接口有自动化测试；公众号复制、知识图解和图片地址不存在阻塞后续开发的问题。

### 阶段 2：知识与大纲闭环，1 至 2 周

- 登录、文章列表和写作档案。
- 两种输入模式、来源管理和真实资料处理。
- 接入真实模型，完成 Knowledge Brief、大纲生成、编辑和确认。

### 阶段 3：正文与编辑闭环，约 2 周

- 全文和分章节生成。
- 局部改写、候选版本和冲突保护。
- 块级编辑、自动保存、撤销和恢复。

### 阶段 4：配图闭环，1 至 2 周

- 配图规划。
- AI 插画生成与候选版本。
- 知识图解模板、渲染和文字编辑。
- 图片上传、替换和压缩。

### 阶段 5：发布闭环，约 1 周

- 三套公众号主题。
- 移动端预览。
- 富文本复制和失败回退。
- 微信兼容性测试。

### 阶段 6：内测优化，1 至 2 周

- 黄金测试集和人工质量评估。
- 异常流程、费用、速度和稳定性优化。
- 修复阻塞发布的问题并准备内测。

一名全栈开发者完成可内测版本的估算为 6 至 9 周。公众号复制、结构化图解和图片地址验证并入阶段 1，必须随基础框架一起完成；资料解析和真实图片模型则在对应功能阶段持续验证。

## 14. MVP 发布标准

满足以下条件后才进入个人内测：

1. 两种输入模式均能完成知识梳理、大纲、正文和配图流程。
2. 一篇 2,000 至 3,000 字、3 至 5 张图的文章可以在 5 分钟目标时间内产生可编辑初稿；用户停留在大纲确认环节的时间不计入。
3. 用户能够逐章和逐块调整，非目标内容不会被后台任务覆盖。
4. 来源和“AI 补充”标记清晰可见。
5. 公众号预览与实际粘贴结果不存在阻塞发布的差异。
6. 自动保存、任务失败、取消、重试和历史恢复均可用。
7. 黄金测试集达到质量阈值，且平均供应商成本不超过目标。

## 15. 后续阶段候选项

只有 MVP 核心指标成立后，才依次评估：

1. 公众号草稿箱接口同步。
2. 多套账号风格和品牌素材。
3. 自动选题、素材库和内容日历。
4. 团队协作、审核与权限。
5. 阅读数据分析和内容复盘。
6. SaaS 套餐、额度与计费。
